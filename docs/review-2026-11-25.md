## Who the user is
Someone standing in or about to visit a town, on a phone, who wants "what is open now and fits before I leave" without an account. Product promise (README.md): no invented facts, nothing to pay for.

Unknown. ## First-run path, from the code
1. Landing, type a town (docs/app.js:334 wireSearch, typeahead 362, doSearch 409).
2. Pick a suggestion, pick() (app.js:429) opens screen s2 with three sections: hours, radius slider, a raw "minutes offset from UTC" number box (docs/index.html:258-298). Defaults arrive 09:00, leave 21:00 (app.js:436-437).
3. "Build my guide" runs runBuild() (app.js:560): geocode, then Overpass, then Wikivoyage, then weather/air/country/transit/photos in parallel, then sun, then open() (app.js:722).
4. The guide opens on the list, or on Now if a plan exists.

## Findings, ranked
F1. Timezone is guessed, and the real answer is already fetched and thrown away. app.js:252-266 guesses from a country table (about 58 listed countries, app.js:181-195) plus DST rules, longitude for the rest. Open-Meteo returns `utc_offset_seconds` in the weather call the build already makes (docs/sources.js:707-708), and nothing in app.js or engine.js reads it (grep of `tzOffsetSeconds` finds only sources.js). A wrong offset makes "open now" wrong by hours, silently, which is the one thing the product promises not to do. Read from the table, not run: ID is fixed at +420 (app.js:190) though Bali is +480; IL has no DST rule though Israel observes it; MX sits in the NA DST set (app.js:203) though Mexico dropped DST in 2022 (outside knowledge, not verified this session); unlisted countries such as PK, BD, MA, AR, CO fall back to longitude, which the code comment itself calls wrong for politically set clocks (app.js:165-176).
F2. The build waits on its three independent network calls one after another. Overpass (up to 45 s per mirror, sources.js:141) finishes, then Wikivoyage, then the live group (app.js:580-625). Only mergePlaces and attachPhotos need two results together. Wall-clock is the sum, not the max.
F3. Two finished branches sit unmerged. origin/fix/tripkit-finding6-now-default (3 commits: keep a night out on the day it started until 04:00, land on the plan for a future-dated trip, a test) and origin/feat/tripkit-in-app-survey (3 commits). Both are listed as STILL OPEN in IDS [PRJ-TK][4]. Past-midnight is the late-evening Now case.
F4. Step 2 is a three-section form before any result. No user data says this loses people, so it is not in the top 3. A Playwright tap count would be the measure if we ever test it.
F5. Counting is off, so every other question stays a guess. Turning it on needs a GoatCounter site made by Atishay (his hand), then one constant.

## Top 3 changes

### 1. Take the timezone from the weather response
What the user notices: opening a town like Bali or Tel Aviv shows the right "open now", and the offset box is pre-filled with the real value, not a guess.
Evidence: app.js:252-266, 181-203; sources.js:707-708; no reader of tzOffsetSeconds.
Expected effect: wrong-offset cases drop to zero wherever Open-Meteo answers; the table stays as the fallback when it is offline. How many real users hit this: unknown.
Proof: unit tests with synthetic weather responses (Bali +480, Tel Aviv +180 in summer, Karachi +300) asserting config.tzOffsetMinutes; existing Porto and Lisbon regressions stay green; node tests/js/run.js.
Risk: weather fails or is slow, then fall back to the table, so no worse than today. The offset is today's, not the trip date's, so a trip across a DST change has the same limit as the table. Cached trips keep their saved offset unless refreshed. Roll back: one commit.

### 2. Fetch Overpass, Wikivoyage and the live group together
What the user notices: the build screen finishes sooner and the steps tick in parallel.
Evidence: app.js:580-625 sequential awaits; Overpass timeout sources.js:141.
Expected effect: build time goes from the sum of the three to the longest one. The real figure is unknown; the proof measures it with mocked latencies, not the live services.
Proof: a Node test with a mock sources layer (selected by an explicit flag, real calls stay the default) where each call takes a fixed delay; assert total is under the longest delay plus a margin; assert the same guide JSON as the sequential build on the same fixtures; one source failing still yields a guide with the same note text.
Risk: Overpass and Wikivoyage are volunteer services; each call is unchanged, only simultaneous (the Overpass wiki documents slot limits per IP, and we still send one request at a time to Overpass). Progress bar and step order change visibly. Roll back: one commit.

### 3. Land the two finished branches
What the user notices: Now no longer flips to tomorrow at midnight on a night out; a future-dated trip opens on its plan; after a stop is marked done a one-question "was this useful" appears once.
Evidence: git diff origin/main...origin/fix/tripkit-finding6-now-default (docs/app.js +8 -3, tests/now-dom.js +25); origin/feat/tripkit-in-app-survey (tests/js/survey.js +30); IDS [PRJ-TK][4].
Expected effect: finding 6 closed; usefulness answers start to exist (they need F5 to be read anywhere).
Proof: existing node tests plus the branches' own tests; Playwright now-dom.js in CI (not locally).
Risk: both branch from 3aff30a and main moved one commit (4813f2d), so a rebase is needed; the 04:00 rollover is a judgement call held in one constant; the survey adds an element to a view I did not render. This re-applies authored work and must not redo or contradict the [PRJ-TK][4] items already merged (5, 7, ask-locals).
